# Аудит графических ассетов меню — 8 ноября 2026 года

**Источник истины:** `survival-open/main`. Объём: пять экранов станции (обзор, задания, корабль, развитие, станция) и связанная карта. Эскизы терминала и дерева — визуальные ориентиры, а не источник игровых данных.

**Тип проверки:** статическая сверка текущих JS/CSS, каталогов ассетов и существующих методических документов. Проверка реальной геометрии на скриншотах с десктопа и мобильного устройства **не выполнена**; не следует считать визуальную готовность подтверждённой.

## Главное решение

Не создавать очередной полный UI-kit. Он уже существует: `studio/menu-kit/art/ui/` (навигаторы, кнопки, сетка дерева, фактура, рамка), `assets/progression/` (узлы, домены, оружие, тактика, фоны), `assets/station-menu/icons-v2.webp`, четыре иллюстрации станций `studio/menu-kit/art/stations/`, четыре фона особых операций `studio/menu-kit/mission/`, боевые и миссионные спрайты `assets/missions/`. Повторная генерация дублирует стили.

## Оставить без новой графики

| Элемент | Причина |
| --- | --- |
| Пять главных вкладок, навигация, кнопки, горячие клавиши | SVG-маски уже есть, цвет/состояние должны быть настоящими; изображение кнопки ухудшит доступность |
| Сами корпуса панелей, линии и декоративная координатная подложка | Уже есть `terminal-frame.svg`, `panel-hatch.svg`, `progression-grid.svg`; не добавлять ещё один орнаментальный слой |
| Узлы навыков как форма и состояния | Есть `node_{selected,ready,mastered,locked}.webp`; проблема выбора изображения — в уникальности символа, а не в новой форме рамки |
| Линии дерева | Текущие связи рисуются SVG по настоящему `requires`, а не по композиции эскиза. Не подменять рисованным фоном с ложными зависимостями |
| Корабль в обзоре, ангаре и развитии | `heroMenuPortrait` берёт реальную ступень и повреждения из `assets/space/hero-evolution/`; общий вымышленный корабль был бы фактической ошибкой |
| Схема оружейных узлов в ангаре | Координаты и доступность вычисляет игра; любые статические отверстия/узлы в нарисованном корпусе создадут несовпадение |
| Карта сектора / территории | Реальные узлы, маршруты и цели должны оставаться SVG/DOM от состояния мира. Декоративная текстура уже есть |
| Полосы корпуса, ресурсы, кнопки покупки, предупреждения, счетчики | Меняются во время игры, обязаны оставаться текстом/HTML/CSS |

## Исправления без генерации

- Дерево всё ещё группирует навыки по уровням в `treeHtml` и `.prog-tier`; выразительная графовая композиция требует корректировки **расположения**, а не подмены графа картинкой.
- Привести карточки выбранного навыка, оборудования и станции к одинаковому порядку: состояние → эффект → условия → цена → действие.
- Уменьшить количество одновременно видимых акцентных рамок и свечения; не добавлять сплошной художественный фон под длинные объяснения.
- Проверить реальную читаемость на 1440×900, 1280×720, 844×390, 932×430, 390×844 и 360×640.
- Важно: панель ведомых и модуль станции должны показывать **игровое состояние**, не одинаковую декоративную картинку вне зависимости от выбранного вида.

## Технические требования к будущим изображениям

1. Сначала сравнить с действующими изображениями на том же масштабе; не генерировать без проверенной уникальной роли.
2. Прозрачный фон, читаемый силуэт, без букв/цифр/подписей, с той же перспективой и освещением, что соседние элементы.
3. Размеры и рабочее разрешение брать из соответствующей группы ассетов, а не назначать произвольно.
4. Не запекать в изображение цены, статусы, количество дронов, условие открытия, расположение станции или порядок соединений.
5. Не добавлять анимации для декоративных кнопок, если они отвлекают от действий; отключать эффекты при `prefers-reduced-motion`.
6. Перед публикацией проверить визуально выбранный/заблокированный навык, несколько развилок, длинные русские названия и навигацию с клавиатуры; затем `node --test arcade/tests/*.test.mjs` и обычный GitHub CI.
7. Работы по управлению мышью, автоматическому огню, HUD и игровому балансу — вне этого проекта и не должны попадать в PR графики меню.

**Итог:** первыми производить *семантические* ассеты для действительно разных навыков. Существующие фоновые изображения, кнопки, рамки, карта и корабль уже достаточны; на них можно тратить усилия только после доказанного визуального дефекта.
