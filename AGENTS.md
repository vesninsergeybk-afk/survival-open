# Правила для разработчиков и ИИ-агентов: «Выживший»

Действуют для всех файлов и задач этого репозитория. Подробности: [docs/PUBLICATION_POLICY.md](docs/PUBLICATION_POLICY.md).

## Три обязательных правила

1. **Единственный источник актуальной игры** — репозиторий `vesninsergeybk-afk/survival-open`, ветка `main`. Все изменения действующей аркады, включая дронов, HUD, вооружение, ангар и окружение, должны попадать сюда через проверяемые изменения. Рабочие ветки и лабораторные прототипы не являются самостоятельными выпусками.
2. **Единственная опубликованная аркада** — https://vesninsergeybk-afk.github.io/survival-open/arcade/. Её собирает и публикует `.github/workflows/publish-pages.yml` из `main` после тестов. Корень GitHub Pages перенаправляет на `/arcade/`; это второй адрес входа, но не вторая сборка. Не публикуйте копию актуальной аркады на Timeweb или под другим URL.
3. **Единая точка входа с VesninMed** — `https://vesninmed.ru/lab/`, где кнопки актуальной игры ведут прямо на https://vesninsergeybk-afk.github.io/survival-open/arcade/. `https://vesninmed.ru/games/survivor/?mission=0` — прежний сюжетный пролог, отдельный архивный режим. Он не должен подменять актуальную игру.

## Перед любым изменением публикации

- Сверьте адреса с [политикой публикации](docs/PUBLICATION_POLICY.md).
- Проверьте `node --test arcade/tests/*.test.mjs` и штатную сборку GitHub Actions.
- Не правьте исходники действующей аркады в `Timeweb/site/games/survivor/`; это историческая копия.
- Если когда-нибудь понадобится изменить публичный адрес, согласованно обновите оба репозитория, проверки, документацию и ссылку на сайте в рамках одного управляемого перехода. Не создавайте конкурирующих ссылок на разные сборки.
